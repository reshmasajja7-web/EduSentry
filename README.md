# EduSentry — AI Learning Workspace & Advising Platform

A single, unified web app: a public landing page with working
registration/login, and — once signed in — a sidebar-driven workspace
covering Dashboard, Learning Workspace, Risk Prediction, Career
Guidance, and Profile. Everything shares one design system, one nav,
and one auth flow; there's no seam between modules.

## Getting started

```bash
npm install
npm run dev
```

Open the URL Vite prints (usually `http://localhost:5173`). You'll land
on the public home page — create an account or log in to reach the app.

```bash
npm run build     # production build → dist/
npm run preview   # preview the production build locally
```

## What's in the app

- **Home** — public landing page with the product pitch and
  Log in / Get started actions.
- **Login / Register** — the frontend calls the Express backend. Accounts are stored in PostgreSQL and passwords are hashed with bcrypt; authenticated sessions use an HTTP-only JWT cookie.
- **Dashboard** — snapshot cards pulling live state from the other
  modules: documents indexed, latest risk score, latest career match.
- **Learning Workspace** — Upload Notes, AI Tutor Chat, Summaries,
  Flashcards, Quiz. Real in-browser document parsing and real
  extractive NLP (see below) — no canned demo data.
- **Risk Prediction (EarlyRisk)** — a two-path flow (college vs.
  self-paced learner), academic-details capture, mock platform
  engagement metrics, a weighted risk score with a live gauge,
  strong/weak factor breakdown, an interactive improvement simulator,
  personalized recommendations, a study plan, and trend charts.
  Rebuilt natively in React (previously an iframe embed of a standalone
  HTML file with its own duplicate sidebar) so it shares the app's
  routing, layout, and nav instead of running as a separate page inside
  a frame. Logic lives in `src/lib/earlyRisk.js`; scoring is a
  transparent heuristic standing in for the trained EarlyRisk model.
- **Career Guidance** — tag-based and free-text interest matching
  across 35 careers, each with a description, skills to build, and
  learning resources. Rebuilt natively in React (previously an iframe
  embed of a standalone HTML file) so it shares the app's routing,
  layout, and state instead of running as a separate page inside a
  frame.
- **Profile** — Personal Information (name, email, course), Learning
  Information (progress across modules, career goal, current day
  streak), Learning Statistics (documents indexed, quizzes taken,
  average quiz score, flashcard sessions, risk checks, career matches),
  and a Learning History feed. All of it is real, derived from an
  activity log (`src/lib/activityLog.js`) that other modules write to
  as you actually use them — nothing here is a placeholder number.

All authenticated routes are gated behind `ProtectedRoute` — visiting
any `/app/*` URL without a session redirects to `/login`.

## Learning Workspace details

- **Upload Notes** — drop a real PDF, DOCX, PPTX, TXT, or MD file. Text
  is genuinely extracted client-side (`pdfjs-dist` for PDF, `mammoth`
  for DOCX, `jszip` + XML parsing for PPTX) and kept in `localStorage`
  so it survives a refresh. Bad or unreadable files show a real error,
  not a fake success state.
- **AI Tutor Chat** — supports general-purpose chat and document-grounded context through server-side Gemini, OpenAI, Anthropic, or DeepSeek integrations. Provider API keys must be configured in `backend/.env`. The zero-key EduSentry Neural RAG option retrieves relevant note excerpts but is not a general-purpose language model.
- **Summaries** — real extractive summarization: sentences are scored
  by keyword frequency and the top few are returned in original order.
- **Flashcards** — generated by pattern-matching "X is Y" / "X refers
  to Y" / "X means Y" sentences in your text; falls back to pairing key
  terms with a sentence they appear in in short documents.
- **Quiz** — cloze (fill-in-the-blank) questions built from your text's
  own key terms, with distractor answers pulled from other key terms
  in the same document.

All of this logic lives in two files, deliberately separated from the
UI:
- `src/lib/fileExtract.js` — file → raw text
- `src/lib/textProcessing.js` — raw text → summaries / flashcards /
  quiz questions / chat answers

## Backend and AI setup

1. Copy `backend/.env.example` to `backend/.env`.
2. Set `DATABASE_URL` to your PostgreSQL connection string and set a strong random `JWT_SECRET`.
3. Configure at least one AI provider key (`GEMINI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `DEEPSEEK_API_KEY`) to enable general-purpose generated answers. Provider usage limits and model availability are controlled by the provider.
4. Install and start the backend:

   ```bash
   cd backend
   npm install
   npm run dev
   ```

5. In another terminal, from the project root, run:

   ```bash
   npm install
   npm run dev
   ```

The frontend calls `/api/rag/generate`; provider keys remain on the server and are not stored in browser localStorage. If a provider is not configured or returns an error, the UI displays the actual error instead of silently presenting a local retrieval result as a generated answer.

The model selector is mapped to these provider model IDs: Gemini 3.6 Flash / Gemini 3.8 Flash, GPT-6.1 Terra / GPT-6 Astra, Claude Sonnet 5, and DeepSeek V4.1 Flash. Model availability can vary by account and provider; provider errors are surfaced in the UI rather than hidden behind a fallback answer.

Registration validates email syntax and checks domain MX records when DNS is available. This does not prove an individual inbox exists; proving mailbox ownership requires verification, which this project intentionally does not use. Phone numbers are optional and format-validated as Indian mobile numbers; format validation cannot prove a number is active or owned by the registrant. Passwords require at least 8 characters, uppercase and lowercase letters, a number, and a special character.

everywhere — public pages, auth, and every app module. They're matched
1:1 to the public landing page (`edusentry_cover.html`) and Profile
module (`edusentry_profile-1.html`) so there's one palette across the
whole product:

| `navy`      | `#0E1220`  | (ink) headings, primary buttons, active state |
| `navyDim`   | `#161B2E`  | button hover / dark panel shade          |
| `gold`      | `#E8A33D`  | (beacon) kickers, numbered badges, highlights |
| `goldTint`  | `#F6E9CE`  | soft beacon backgrounds                  |
| `paper`     | `#F4F0E6`  | (parchment) page background              |

| `sage`      | `#5C8770`  | positive/low-risk state                  |

(IBM Plex Mono).

Shared components in `src/components/` (`Logo`, `ModuleHeader`,
`Block`, `Tag`, `Btn`, `Sidebar`, `PublicHeader`) keep every screen —
public or authenticated — visually and structurally consistent. `Logo`
is the lighthouse/beacon mark used everywhere the brand appears (public
header, sidebar, browser favicon) — a sentry watching over a student's
learning.

## Known limitations (worth saying out loud in your submission)

- Auth is a client-side prototype: accounts live in `localStorage`,
  not a real database, and there's no password hashing. That's fine
  for a demo/capstone walkthrough; swap in a real backend (and hashed
  passwords) before this handles real accounts.
- Risk Prediction and Career Guidance use transparent, hand-tuned
  heuristics rather than trained ML models — the interfaces and data
  flow are built so a real model (e.g. the EarlyRisk classifier) can
  be dropped in behind the same function signatures later.
- PDF text extraction won't work on scanned/image-only PDFs (no OCR) —
  it'll show a clear "couldn't find readable text" error rather than
  silently failing.
- The zero-key EduSentry Neural RAG option only retrieves/synthesizes uploaded material. General-purpose generated chat requires a configured external provider. Live provider operation also depends on valid credentials, model access, quota, and current provider model availability.
- Flashcard/quiz quality depends on how your source text is written —
  documents with clear "X is Y" definitions produce much better cards
  than dense prose without them.


## Free-tier AI tutor setup

This build removes OpenAI, Anthropic and DeepSeek from the AI Tutor model selector. Supported hosted providers are Google Gemini and Groq; both may impose quotas, rate limits or temporary availability restrictions, so this project cannot promise unlimited free use. Keep billing disabled if you require zero cost. Configure `GROQ_API_KEY` and/or `GEMINI_API_KEY` in `backend/.env` (copy from `backend/.env.example`) and restart the backend. Never share or commit `.env` files.

Login uses one field for either the registered email address or phone number, plus the account password. Password reset remains email-only and uses the email verification code flow.


Free AI model configuration: set `GEMINI_API_KEY` for Gemini free-tier models, `OPENROUTER_API_KEY` for the explicitly free OpenRouter model choices, and optionally `GROQ_API_KEY` if your Groq account provides free-tier access. Do not enable billing or add credits if you require zero cost. Free endpoints are rate-limited and may be temporarily unavailable.
